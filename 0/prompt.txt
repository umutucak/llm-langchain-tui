2. Key Technical Concepts:
   - LangChain (`langchain` unified package v1.x), `langchain-ollama`'s `ChatOllama`, `langchain.agents.create_agent`.
   - LangGraph `StateGraph`/`CompiledStateGraph`, the `Pregel` runtime, channels, checkpointers.
   - LangGraph's experimental **v3 streaming protocol**: `agent.stream_events(..., version="v3")` → `GraphRunStream` (caller-driven pump, no background thread); `.messages` is a `StreamChannel[ChatModelStream]`, one `ChatModelStream` pushed per LLM call at `message-start`; `.text`/`.reasoning` are lazy `SyncTextProjection`s that pump the *entire* underlying message if drained to exhaustion (root cause of the original streaming bug); raw `for event in message:` iteration yields protocol events (`content-block-delta` with `delta.type` of `text-delta`/`reasoning-delta`) in true arrival order without that problem.
   - `Checkpoint` = full snapshot of all channel values at one graph step (not a diff); one checkpoint per graph *step* (superstep), not per user turn. `BaseCheckpointSaver.put(config, checkpoint, metadata, new_versions)` is internal Pregel plumbing, not meant to be called by app code.
   - `SqliteSaver` (`langgraph.checkpoint.sqlite`, package `langgraph-checkpoint-sqlite`): schema `checkpoints(thread_id, checkpoint_ns, checkpoint_id, ..., PRIMARY KEY(thread_id, checkpoint_ns, checkpoint_id))` and `writes(...)` — every `.put()` inserts a new row, never overwrites; `.get_tuple()` without an explicit checkpoint_id does `ORDER BY checkpoint_id DESC LIMIT 1`.
   - `agent.get_state(config)` → `StateSnapshot` (`.values`, `.next`, `.config`, `.metadata`, `.created_at`, `.parent_config`, `.tasks`, `.interrupts`); `.values["messages"]` gives the full bidirectional conversation for a thread at any time, independent of an active stream (internally calls `checkpointer.get_tuple(config)`).
   - `add_messages` reducer: merges by message ID, so resending only the newest `HumanMessage` each turn is sufficient — checkpointed history isn't erased.
   - `langchain_ollama`'s `_convert_messages_to_ollama_messages`: purely structural tool_call serialization, no validation against currently-bound tools — no crash risk sending tool-call history to a toolless `.invoke()`, but a plausible chat-template/distributional mismatch risk, motivating `strip_tool_context`.
   - SQLite behavior: `DELETE` never shrinks the on-disk file size (only `VACUUM` does); parameterized `?` queries vs. unsafe f-string interpolation; `ON CONFLICT ... DO UPDATE` upsert pattern.
   - Graph visualization: `agent.get_graph().print_ascii()` (needs `grandalf`, DAG-only renderer, silently drops cycle edges) vs. `agent.get_graph().draw_mermaid()` (correctly renders cycles, e.g., the `tools -.-> model` back-edge).
   - Architectural decision: deterministic out-of-band `model.invoke(...)` call preferred over tool-calling for a deterministic "always fires once" side effect (auto-titling), to avoid probabilistic tool-triggering, permanent per-turn tool-schema context overhead, and needing to filter the call out of tool-visibility code paths.
